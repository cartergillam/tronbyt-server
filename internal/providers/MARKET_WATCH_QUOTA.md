# Market Watch Basic-plan budget

Quote identity is authorized owner scope + canonical listing ID + expected currency. Legacy AUTO or exchange-qualified symbols remain separate identities so an unspecified venue cannot silently substitute for a selected listing. Name, order, Focus/Ticker, colors, device and installation do not enter quote keys. Overlapping watchlists reuse individual listing snapshots within the same owner credential scope, and adapter serialization coalesces simultaneous refresh decisions. Quota state is persisted separately from the existing in-process quote cache.

Safe defaults are: eight symbols per display/watchlist; 15-minute open-market freshness; 60-minute closed/unknown freshness; 500 total reserved API credits per underlying Twelve Data key per UTC day; six credits per key per provider minute; and at most 16 distinct quote listings requested per key per UTC day. Administrators can choose stricter limits or slower refreshes with `MARKET_MAX_SYMBOLS`, `MARKET_OPEN_REFRESH_MINUTES`, `MARKET_CLOSED_REFRESH_MINUTES`, `MARKET_DAILY_CREDIT_BUDGET`, `MARKET_MINUTE_CREDIT_BUDGET`, and `MARKET_NEW_SYMBOLS_DAILY`. Values cannot exceed the safe ceilings or make refreshes faster than defaults.

The shared database ledger stores only a SHA-256 fingerprint of the underlying provider key, aggregate minute/day counters, blocked-request totals and the bounded daily symbol set. Transactions serialize reservations across simultaneous calls and server instances. Reservations are made before requests and retained after ambiguous network failures. If the ledger is unavailable, the provider request is blocked. Minute buckets follow Twelve Data's per-minute reset; daily buckets reset at 00:00 UTC. A five-symbol `/quote` batch reserves five credits. `/symbol_search`, `/time_series` credential validation and `/logo` metadata each reserve their documented one-credit endpoint weight. Provider `api-credits-left` and `api-credits-used` headers constrain current-minute headroom and are retained for owner diagnostics; they are never presented as daily remaining credits. The server does not poll `/api_usage`.

Uncached quote requests use batches of at most five symbols and preserve independent per-symbol result/error handling. With a six-credit minute cap, an eight-symbol cold watchlist can fetch five symbols and defer the remaining three until the next eligible minute. Concurrent render requests are coalesced in-process; the persistent database reservation still enforces the aggregate across server instances. Valid cached/LKG quotes are returned when a refresh is deferred or fails (up to the existing 72-hour LKG bound), marked STALE where applicable. Without a usable snapshot the renderer receives a sanitized rate-limit/unavailable state. PLAN REQUIRED and other per-symbol classifications remain independent.

The owner-only Market Watch diagnostic reports sanitized per-symbol stale state and the logical credential ID, plus the last observed provider credits used, configured limits, locally reserved minute/day use, remaining local budgets, blocked-request count and next eligibility. It never returns a secret or key fingerprint. The daily counter is an exact count of this server's reservations, not a claim about calls made by external consumers of the same Twelve Data key.

Eight symbols × approximately 26 refresh cycles in a 6.5-hour US session = 208 quote credits per display. If ben-frame and carter-frame use the same underlying key and disjoint eight-symbol lists, quote-only usage is approximately **416 credits/day**. The 500-credit aggregate leaves up to 84 credits for searches, validation, logo metadata, retries and other users of the key; overlap or closed markets reduce quote use. This is an estimate, not a guaranteed daily total. Twelve Data documents Basic as eight API credits per minute and 800 per day, with the daily reset at midnight UTC; this policy deliberately stays below those limits.

Search results: 24-hour freshness with seven-day LKG, normalized query and credential scope; errors aren't stored as successful results. Remote logo metadata/images: 30-day freshness with 30/90-day LKG. Permanent unavailable/unsafe logo results: 24-hour negative cache. AAPL and MSFT US NASDAQ/USD listings (including XNGS/XNMS/XNCM segments) use embedded approved transparent SVGs, resolved before remote caches, normalized once per versioned logo-cache key and cached for a year, without provider requests. Failed acquisition retains ticker-letter fallback. Logo keys include a normalization revision and curated asset fingerprint. That fingerprint and device assignment enter Market Watch render context identity. Cached quote snapshots have a separate read-only revision so new data updates rendered output without any fingerprint operation triggering a provider request. The Apple source fixture is an opaque black-on-white JPEG; the former Pixlet logo box also filled the canvas pale gray. Microsoft's former pale background made transparent gaps/borders visible. Explicit overrides eliminate dependence on unsuitable provider backgrounds without stripping white from arbitrary logos or modifying sports normalization.

All quota tests use mock HTTP transports. Provider and server cache tests demonstrate reuse across render modes, concurrent calls, and installation saves. Persistent ledger tests cover atomic reservations, restart survival, daily reset, provider header headroom and symbol churn. The two-display quote-only estimate is 416 credits/day at the defaults.


## Credentials and device assignment

The existing AES-GCM credential store already supported multiple IDs per provider/owner. Labels and creation/update metadata make that visible; IDs remain stable and globally unique for legacy compatibility. iOS creates unique IDs automatically and displays labels. Device `market_credential_id` stores the owner-owned logical credential, never ciphertext/plaintext. Owner-only PUT `/v0/devices/{id}/market-credential` assigns/clears it; GET returns the ID/label to the owner and only `configured` to authorized members. Credential lists include assigned device IDs for owner UI. Members cannot create, replace, disable, delete, validate or assign keys and cannot change installation overrides. Member stock search ignores arbitrary client credential selection and uses the device assignment.

Resolution: nonempty installation override other than legacy schema default `market-primary`/`__device__` → device assignment → legacy owner `market-primary` → SETUP REQUIRED if absent/disabled/wrong provider. A saved `market-primary` is treated as automatic when an assignment exists. Owner-configured legacy nondefault installation overrides remain supported. Authorization derives owner scope from the authorized device, never a client-provided owner ID. Cache scopes include owner + credential ID + encrypted-key version; replacement invalidates only that credential's quotes/search/failure state, and disabled keys cannot serve fresh cached quotes. Same assigned credential + listing shares snapshots across devices. Separate credentials continue to isolate quote/search/backoff state; quota reservations instead use a private SHA-256 fingerprint of the underlying key so duplicate records share the budget without exposing the key.

## Canadian symbols

`PLZ.UN` is a valid Twelve Data TSX/XTSE listing: https://twelvedata.com/markets/108274/stock/tsx/plz.un . Dots were already preserved by server and iOS validation, canonical IDs and URL encoding. The error classifier formerly mapped every provider 400/404 to BAD SYMBOL even if its message identified a plan/subscription restriction. Entitlement messages now take precedence over those generic codes. A valid exact Canadian selection receiving a plan error becomes PLAN REQUIRED; a truly invalid-symbol response remains BAD SYMBOL. Search `access.plan` is preserved and iOS displays a nonblocking upgrade notice. Public discovery is not proof that an individual API key can quote a listing: https://support.twelvedata.com/en/articles/5332349-commercial-and-personal-usage . No historical provider response or physical-device runtime trace was available in these repositories, so the precise original account entitlement and exact stale physical cache layer cannot be asserted from tests alone.

The physical Apple issue has two confirmed code-level causes: the override was evaluated inside a cache miss callback, so cached remote artwork won, and the approved-ID map excluded NASDAQ market-segment MICs. Overrides now win before all remote/legacy caches, accepted NASDAQ MICs retain exact listing identity, and asset/normalization fingerprints invalidate only Market Watch logo/render output. Microsoft uses identical precedence/versioning without changing its approved asset.

CLOSED messages are absent from both display modes. Closure does not mark a valid closing snapshot stale. Actionable provider errors, explicit EOD/delayed indicators and genuine STALE conditions remain. Ten-symbol ticker uses sequential bounded current/next-card strips: 960 one-pixel frames × 55 ms = 52.8 seconds, below the 60-second Market Watch encode allowance and 2,000-frame Pixlet ceiling. This also works with the installed older Pixlet's Marquee spatial cap. No animation/frame performs provider I/O.

## Carter and Ben credential setup

Create two distinct Twelve Data API keys and store each as a separate managed credential through the existing owner-only **Settings → Provider Credentials** screen. Give each record a clear label/ID (for example `Carter · Market` and `Ben · Market`), validate it, then use **Settings → Provider Credentials → Device Market Credentials** to assign the matching credential to `carter-frame` or `ben-frame`. Assignments are explicit and this release does not change saved devices automatically. Secrets are encrypted at rest and are not returned after entry. Per-key daily/minute budgets are separate for distinct key values; records that contain the same actual key share one budget.

Only an owner profile can add, validate or assign credentials. A Ben household-member session can manage the apps on devices assigned to him, but cannot manage provider secrets or select Carter's credential. If `ben-frame` remains owned by Carter's server account, the owner must perform the one-time entry and assignment of Ben's separately issued key; Ben can enter it himself only through an owner profile for the account that owns that device. This is an owner-level provisioning step, not server-administrator access, and no key should be sent through chat, email, a URL, or device configuration.
